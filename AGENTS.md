## What this is

JavaScript wrappers for [AnonCreds](https://github.com/hyperledger/anoncreds-rs): `@hyperledger/anoncreds-shared` (the API), `@hyperledger/anoncreds-nodejs` (bindings over FFI with koffi) and `@hyperledger/anoncreds-react-native` (bindings over JSI, in C++). Both binding packages download the prebuilt native library on install.

## Layout

- `packages/anoncreds-shared`: the API and the `NativeAnoncreds` interface that both bindings implement. `tests/` has the tests for both bindings.
- `packages/anoncreds-nodejs`: the Node.js bindings.
- `packages/anoncreds-react-native`: the React Native bindings. `src/ReactNativeAnoncreds.ts` passes options objects to the C++ in `cpp/`, which reads them by property name. A name that differs between the two sides is only caught by the React Native tests.
- `examples/anoncreds-react-native-example`: an Expo app in the pnpm workspace that runs the tests on a device. `ios/` and `android/` are generated by `expo prebuild` and not committed.

## Checks

Run from the repo root after every change, and fix what they find:

- `pnpm style:fix`: Biome formatting and lint.
- `pnpm types:check` and `pnpm build`.
- `npx tsc --noEmit` in the example app.

## Tests

The tests in `packages/anoncreds-shared/tests` run on Node.js with Vitest (`pnpm test`) and in the example app with [React Native Harness](https://react-native-harness.dev). In the app, `tests/shared.harness.ts` loads all of them and Metro resolves their `vitest` import to `react-native-harness`, so write them with the `describe` / `test` / `expect` that both have. Use the `react-native-harness` skill (`.claude/skills/react-native-harness/SKILL.md`) to write or debug Harness tests.

From the repo root:

- `pnpm test:android` and `pnpm test:ios`: an emulator and a simulator. Harness creates or boots the device and installs the app.
- `pnpm test:android:device` and `pnpm test:ios:device`: the phone connected with a cable (USB debugging on Android; unlocked and trusting the Mac on iOS).

Each script builds the app first (`examples/anoncreds-react-native-example/harness/run.mjs`), so changes to the C++ are included. Jest arguments go at the end, e.g. `pnpm test:android -t "presentation"`.

The example uses the newest Expo SDK. CI also runs the tests with older SDKs, and with them older React Native versions (`.github/workflows/ci.yml`). To do that locally, run `node harness/use-expo-sdk.mjs <sdk>` in the example, then the tests, then `git checkout` the files it changed.

## Dependencies

- react and react-native are in the `catalog:` in `pnpm-workspace.yaml`, shared by the React Native package and the example, so Metro bundles a single copy. Bump them there, with the Expo SDK of the example.
- pnpm 12 (`packageManager`). Its settings are in `pnpm-workspace.yaml`, `.npmrc` is only read for auth. pnpm only runs install scripts of packages listed in `allowBuilds`, and doesn't resolve versions published less than a day ago.
- The repo uses pnpm's hoisted node linker. After a big dependency change, delete `node_modules` and install again if the build fails on modules that can't be found: pnpm leaves outdated nested packages behind.
- The packages use the newest TypeScript from the catalog. The example pins the TypeScript version its Expo SDK supports.

## Commits and releases

Commits use Conventional Commits, e.g. `fix(react-native): read the revocation status list when creating a credential`. Changes to published packages need a changeset in `.changeset/` (the `@hyperledger/*` packages version together). Releases are published from CI with changesets.
